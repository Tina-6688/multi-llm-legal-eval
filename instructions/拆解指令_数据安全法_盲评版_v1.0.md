# 《数据安全法》拆解指令（盲评版 v1.0）

> 盲评要求：输出中不得出现模型名、平台名、历史分数；标题只写《数据安全法》规则架构。
> 本指令只规定怎么拆、怎么输出、怎么自查，不提供任何具体条款号或标准答案。

## 一、输出格式规范

模型最容易在格式上翻车，先定死：

### 1.1 整体结构

```text
# 数据安全法 · 规则架构

## 【一】条文忠实转写与术语表
### 1.1 术语统一表        ← markdown 表格
### 1.2 逐条转写          ← 按条分 ###

## 【二】决策树
### 树目录               ← markdown 表格
### T1 <树标题>          ← 每棵树一个 ###
（树体在代码块内）

## 【三】条款-规则映射表     ← markdown 表格

## 【四】可执行规则（YAML）  ← 每块一个 ```yaml

## 【五】覆盖账本与自检
### 5.1 条款→树 映射表
### 5.2 未覆盖清单
### 5.3 自检表

## 【二-附】规则清单        ← 非判定型条款

## 【六】跨法交叉提示        ← markdown 表格
```

### 1.2 决策树的画法（**最容易失败的一环**）

**必须放在 ` ``` ` 代码块里**，否则 Markdown 会把空格吃掉、把 `│` 当表格分隔符，树就散架了。

**字符集只用这四个**：`├─`、`└─`、`│`、`→`

标准样式：

````text
### T1 数据分类分级保护制度

适用前提：数据处理者在中华人民共和国境内开展数据处理活动。

```text
T1 【树标题】
├─ Q1 【判定条件一】？
│  ├─ 是 → 【结论或动作】[第X条] [义务]
│  │  ├─ Q1.1 【下一层判定】？
│  │  │  ├─ 是 → 【动作】[第X条] [义务]
│  │  │  └─ 否 → 【后果】[第X条] [禁止]
│  │  └─ Q1.2 【并列判定】？
│  │     ├─ 是 → 转 T2（前提见 T2）[第X条]
│  │     └─ 否 → 【不适用说明】
│  └─ 否 → Q2 【下一个判定】？
│     ├─ 是 → 【动作或结论】[第X条] [授权]
│     └─ 否 → 【兜底结论】→ 见 T3
└─ 终点：本树所有叶子均落在「动作 / 结论 / 阈值」，无以问句收尾
```

> 📌 **上面只是"形状样板"，其中的「第X条」一律是占位符。**
> 指令里**不提供任何真实条款号**——真实条款号由模型依据原文自己填。
> 这条样板只回答一个问题：**树长什么样**。
````

**铁律**：
1. 树体必须在代码块内，代码块语言标 `text`
2. 每层缩进 2 空格 + `├─`/`└─`
3. 分支编号用 `Q1`、`Q1.1`，方便人工抽查
4. 每个叶子后面标 `[条款号]` + `[义务]/[禁止]/[授权]/[倡导]`
5. 叶子**不能**以问句结尾
6. 一棵树深度 ≤ 5 层

### 1.3 表格与 YAML

- 表格一律用 Markdown 管道表，**列数固定**，不要合并单元格
- YAML 每块独立 ` ```yaml ` 代码块，**多块之间用 `---` 分隔**（否则 `safe_load_all` 会串行报错）
- YAML 里凡是含中文标点的字符串，**整句用双引号包住**（以往测试 里 某样本 就是被一行裸中文毁掉整份）

### 1.4 格式自检（让模型自己在末尾查一遍）

```text
【格式自检】
1. 所有决策树是否都在 ```text 代码块内？           是/否
2. 是否存在没有落在「动作/结论/阈值」上的叶子？      是/否
3. 是否存在深度超过 5 层的树？                      是/否
4. 所有 YAML 块是否都能被 yaml.safe_load_all 解析？  是/否（自查：有无裸中文引号）
5. 是否存在占位符 XXXXXXXX / ??? / [待填]？          是/否
```

## 二、拆解指令模板

```text
你是一名「中国数据合规规则架构师」。

法律名称：《中华人民共和国数据安全法》（现行有效版本，共55条、7章）
如为自行检索模式：请以全国人大官网 / 国家法律法规数据库的现行版本为准，并在开头注明你采用的版本与来源。

请完成六件事，用中文输出。**全文必须是严格的 Markdown 格式**，严格按【一】～【六】作答。

────────────────────────
【一】条文忠实转写与术语表
────────────────────────
1. 逐条摘录原文，完整保留「第X条 / 第（X）款 / 第（X）项」层级编号。不合并、不省略、不改顺序、不改写。
2. 义务强度必须原样保留，并在句后打标签：
   - 「应当 / 必须」→ [义务]
   - 「不得 / 禁止」→ [禁止]
   - 「可以 / 有权」→ [授权]
   - 「宜 / 鼓励」→ [倡导]
3. 输出「术语统一表」（Markdown 表格），列：术语 | 首次出现条款 | 后文统一写法。
   必须覆盖本法出现的核心主体与客体术语。
4. 原文中的「除……外」「但……」「另有规定的除外」等但书与除外情形，**必须单独成行保留**，不得并入主干句。
5. 逐条转写用「### 第X条 条文标题」分节，一条一节。

────────────────────────
【二】决策树（必须多棵，禁止一棵大树）
────────────────────────
■ 第一步：输出「树目录」表，列固定为：
  树ID | 树标题 | 覆盖条款区间 | 本树回答的问题 | 叶子数

■ 第二步：拆树规则（机械执行，不得自行发挥）
  1. 拆树单位 = 原文自带的「章 / 条 / 条下的款、项」中含条件判定的那一层。
  2. 归属唯一：每一个条款号只能落在唯一一棵树里；需引用他树前提时写「（前提见 T3）」，不要复制整段。
  3. 单棵树深度不得超过 5 层，超过请按下一层编号继续拆。
  4. 每棵树叶子必须落在「可执行的动作 / 明确的结论 / 具体的阈值」上，**不得以问句收尾**。
  5. 目标树数：7–12（低于下限说明没拆开，高于上限说明拆太碎）。
  6. 每棵树开头加一行「适用前提：」，使该树可独立读懂。
  7. 每个叶子后标注来源与强度，格式：[第X条] [义务]

■ 第三步：树的画法（强制）
  - 每棵树必须放在 ```text 代码块内（否则 Markdown 会吃掉缩进与竖线）。
  - 只用 ├─ └─ │ → 四个符号画分支；缩进 2 空格一层。
  - 分支编号 Q1 / Q1.1 / Q1.1.1，便于人工抽查。
  - 每棵树最后加一行「终点：」说明该树叶子全部落在动作/结论/阈值上。

■ 第四步：禁止事项
  - 禁止把不同章的内容合并进同一棵树。
  - 禁止只给概数：出现「若干情形」「下列情形」「等」时，必须把原文能列举的逐项展开成子节点；
    原文确实未列举的，写「原文未列举」。

────────────────────────
【三】条款-规则映射表
────────────────────────
Markdown 表格，列固定为：
规则ID | 条款号 | 规则类型 | 触发条件 | 义务或后果 | 例外/但书 | 原文关键句（中文原句逐字）
规则类型取：definition / condition / obligation / exception / procedure / penalty。

────────────────────────
【四】可执行规则（YAML）
────────────────────────
按下列 Schema 输出。**每块独立 ```yaml，块间用 --- 分隔，含中文的字符串整句用双引号包住。**

rule_id: DSL-001
title: 规则标题
law: 中华人民共和国数据安全法
article: 第N条            # ← 占位符，由你依据原文填写真实条款号
rule_type: condition        # definition / condition / obligation / exception / procedure / penalty
description: "给人看的规则描述"
condition:
  all:
    - field: 字段名
      operator: equals      # equals / in / gte / lte / exists / not_exists
      value: "值"
  any: []
  none: []
action:
  - type: obligation         # obligation / permission / prohibition
    description: "应采取的措施"
exception:
  - description: "例外或但书"
legal_basis:
  article: 第N条          # ← 同上，占位符
  quote: "原文中文原句，逐字"
verification:
  status: pending

注意：原文「可以/有权」→ action.type 必须 permission；原文「不得」→ 必须 prohibition。

────────────────────────
【五】覆盖账本与自检
────────────────────────
1. 条款→树 映射表：把原文每一个条款号（第X条、第X款、第X项）逐行列出，写明落在哪棵树、哪个节点。一行一个，不许合并。
2. 未覆盖清单：无法成树的条款（纯定义/纯禁止/纯程序性）单独列出，说明已放入【二-附】，且它们在映射表里仍要有行。无遗漏写「未覆盖条款：无」。
3. 自检表（Markdown 表格）：
   - 树的总数：__
   - 是否存在条款跨树重复：是/否
   - 是否存在未覆盖条款：是/否
   - 最深树层数：__
   - 全文是否有「可以」被写成「应当」：是/否

────────────────────────
【二-附】规则清单（非判定型条款专用）
────────────────────────
纯定义、纯禁止、纯授权、纯程序性条款（不含「如果/除非/除……外/在……情形下」结构）不要硬画树，
统一放这里：规则ID | 条款号 | 类型 | 内容。它们同样要出现在【五】的覆盖账本里。

────────────────────────
【六】跨法交叉提示（中文法域必做）
────────────────────────
本法与《个人信息保护法》《网络安全法》存在交叉。
凡你判断「此条需另一部法才能完整适用」的地方，列一张表：
本条款号 | 涉及的另一部法 | 需要哪一条 | 判断依据
⚠️ 不得编造另一部法的条文内容；不确定的写「需人工核对另一部法原文」。

────────────────────────
【七】格式自检（末尾必交）
────────────────────────
1. 所有决策树是否都在 ```text 代码块内？ 是/否
2. 是否有叶子以问句收尾？ 是/否
3. 是否有树深 > 5 层？ 是/否
4. YAML 是否全部可解析（有无裸中文引号/未转义）？ 是/否
5. 是否有占位符 XXXXXXXX / ??? / [待填]？ 是/否

硬性约束：
1. 只依据给定原文（或你检索到的现行全文）作答，不得引入原文之外的法规内容。
2. 不得编造条款号；每个条款号都必须能在原文中找到。
3. 需要外部条文才能判断的，写进【六】，不要自行补充。
4. 若你认为题目给出的法规名称、施行日期、版本有误，必须指出，不要照抄。
5. 不要输出寒暄或与任务无关的说明。
6. **输出必须是严格 Markdown**：标题用 #，表格用管道表，树与 YAML 用代码块。

下面是原文（或：请自行检索《中华人民共和国数据安全法》现行有效全文）：
<<<此处粘贴全文>>>
```

## 三、本法结构提醒

```text
本法结构特征：同时包含「制度类」与「义务类」两类条款。
- 制度类（如分类分级、安全审查、出口管制等）本质是「适用范围 → 触发条件 → 法律后果」，
  不要画成是非单选题；
- 义务类（如管理制度、技防措施、风险监测与处置）要落到「谁、在什么条件下、必须做什么、不做的后果」；
- 两类不要混在同一棵树里，也不要用同一棵树的叶子类型（制度类叶子多是"适用/不适用"，义务类叶子多是"动作"）。
```
