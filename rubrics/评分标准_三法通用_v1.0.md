# 法律条文拆解评分标准（三法通用 · 盲评版 v1.0）

> 用途：给独立裁判对匿名输出样本打分。
> 原则：只评交付物，不评模型身份、平台快慢、历史分数或运行故障。
> 本文件不包含模型名称、历史排名、平台评价，避免锚定效应。

## 适用法律

| 法律 | 条数 | 章数 | 版本 |
| --- | ---: | ---: | --- |
| 《数据安全法》 | 55 | 7 | — |
| 《个人信息保护法》 | 74 | 8 | — |
| 《网络安全法》 | 81 | 7 | **2025-10-28 修正，2026-01-01 施行** |

> 原文校准：以国家法律法规数据库（flk.npc.gov.cn）下载的官方文本为准；如本文件与原文冲突，以原文为准。
> 考点清单仅用于覆盖性核对，不是条款号答案，按法律分列于 `考点清单/`。

## 一、盲评纪律

- 只看到匿名编号（如 A1、A2、B1、B2），不知道对应模型或平台。
- 输入模式 A＝提供原文；B＝自行检索。两种模式分开评。
- 样本不完整，按不完整扣分，不需要知道中断原因。
- AI 只做初评与证据整理，verified 只能由人工终审打。

## 二、评分标准（六维）

### 2.1 维度与权重

| 维度 | 权重 | 判什么 |
| --- | --- | --- |
| **① 条文忠实度与术语一致** | **25%** | 有没有篡改义务强度、有没有丢但书、术语是否统一、条款号是否真实 |
| **② 决策树结构与覆盖** | **25%** | 多树合规性、树目录、深度、叶子质量、概数展开、归属唯一 |
| **③ 逻辑正确性** | **20%** | 且/或、条件方向、例外挂载位置、否定倒置 |
| **④ 可追溯性** | **15%** | 覆盖账本、原文引用逐字、条款号抽检 |
| **⑤ 可执行性** | **10%** | YAML 可解析、字段有定义、义务类型编码正确 |
| **⑥ 诚实度** | **5%** | 缺失项标注、跨法不确定是否标明、有无自造条文 |

**综合分 = Σ(维度得分 × 权重) ÷ 5 × 100**

### 2.2 各维度评分细则

**① 条文忠实度与术语一致（25%）**

| 分档 | 标准 |
| --- | --- |
| 5 | 条款号全对；无义务强度篡改；但书完整；术语全文唯一；未合并条款 |
| 4 | 上述各项有 1–2 处轻微问题（如个别术语措辞不统一） |
| 3 | 有 1 处**义务强度篡改**，或有条款被合并，或有但书丢失 |
| 2 | 义务强度篡改 ≥3 处，或术语系统漂移（同一概念三种叫法） |
| 1 | 大段改写原文、出现原文没有的表述 |

**② 决策树结构与覆盖（25%）——含前置否决**

| 判定 | 后果 |
| --- | --- |
| 输出仍是**一棵大树**（无树目录、无多树） | **直接 ≤2 分**，不论覆盖多全 |
| 树目录缺失，或树ID/覆盖区间与正文对不上 | 扣 1 分 |
| 存在条款跨树重复，或账本与正文不一致 | 扣 1 分 |
| 树深超 5 层且未继续拆 | 每超 1 层扣 0.5 |
| 概数未展开（「重要数据目录」等未逐项列出） | 每处扣 0.5 |
| 叶子以问句收尾（半截树） | 每处扣 0.5 |

**③ 逻辑正确性（20%）**

重点查 以往案例中复现过的高频错：

| 错误类型 | 实例（以往案例 真实发生过） |
| --- | --- |
| 且/或写反 | 样本 A 把「必须逐一涵盖」写成「任一即触发」 |
| 条件语义倒置 | 样本 B 把「充分通知」的构成要件当触发条件，规则只在已合规时才命中 |
| 例外挂错位置 | 样本 D 把 TIN 例外挂在「是否获取信息」的否分支上 |
| 把例外放大成整体豁免 | 样本 B 的 AML-003：TIN 状态一项例外，连带豁免了三项义务 |
| 结果状态当触发条件 | 样本 C 拿「账户已关闭」当判定前提 |

**④ 可追溯性（15%）**

- 覆盖账本逐行可核 + 未覆盖清单诚实 → 5 分档
- 原文 `legal_basis.quote` 与官方法条逐字一致 → 抽检 5 处，每错 1 处扣 0.5
- 账本缺行或与正文对不上 → 上限 3 分

**⑤ 可执行性（10%）**

- YAML 能否 `yaml.safe_load_all` 直接解析（以往案例中 样本 B 因**一行引号**导致整份不可解析）
- 条件字段是否有定义（样本 A 45 个字段只有 12 个有定义 → 规则库跑不起来）
- 义务类型编码：may→permission、must→obligation、不得→prohibition

**⑥ 诚实度（5%）**

- 【需人工确认】标注数量与质量
- 缺失信息是否单列、是否混进正文
- 跨法引用的不确定项是否标明（而不是自己编一条另一部法的内容）
- 是否出现自造阈值

### 2.3 一票否决项（不参与加权，直接判不合格）

| 项 | 判据 |
| --- | --- |
| **编造条款号** | 出现官方原文中不存在的条款号 |
| **占位符残留** | 出现 `XXXXXXXX`、`???`、`[待填]` 等未清理痕迹（以往案例中 样本 D 残留 13 处 → 交付事故） |
| **交付缺失** | 正文没有 YAML/树，只给了文件路径或沙盒地址 |
| **编造另一部法** | 【六】跨法表里写了未经核验的另一部法条文内容 |

### 2.4 两个必须分开的分数（沿用以往口径）

| 分数 | 含义 | 用途 |
| --- | --- | --- |
| **实际分** | 你手上这份文件能不能用（交付视角） | 决定要不要重跑 |
| **潜在分** | 模型本身能做到什么程度（能力视角，扣掉 UI/导出问题） | 决定值不值得再给它一次机会 |

**归因规则**：内容根本没生成 → 扣模型分；内容生成了但导出不出来 → **不扣模型分**，只记「平台交互损耗」。

### 2.5 新增检查项（不计分，写进裁判评语）

**可核对成本**：人工核对这份产出预计需要多少分钟（树数 × 每棵抽查点 + 账本行数）。
这一项直接决定它能不能进你的日常流程。

## 四、裁判流程

沿用盲评三层流程，**每一层都留证据**：

```
第 1 层｜机械体检（脚本，客观可复现）
   ├─ 统计：文件大小、独立树数、树形节点数、规则条数、映射表行数、账本行数
   ├─ YAML 可解析性（yaml.safe_load_all 逐块试）
   ├─ 义务类型统计（obligation / permission / prohibition 各几条，扫码即可发现 may 编码错误）
   ├─ 占位符与乱码扫描（XXXXXXXX / ??? / 待填）
   └─ 条款号抽取 → 与官方原文比对（真伪 + 是否越界）
        ↓
第 2 层｜逐样本精读（每份产出按六维打分 + 逐字证据）
   └─ 关键指控必须附「原文原句 + 产出原句」对照，不采信无证据的判断
        ↓
第 3 层｜裁判独立复核（我不采信自己第 2 层的结论）
   ├─ 抽检 5 处条款号、5 处 quote 逐字、5 处义务强度
   ├─ 复核所有「逻辑错误」指控（且/或、条件方向、例外挂载）
   └─ 区分「能力问题」与「平台交付问题」，分别计分
        ↓
输出：评分表（含实际分 / 潜在分 / 可核对成本）+ 横向对比 + 选型建议
```

**复核纪律（沿用你定的）**：
1. 官方原文是唯一依据，我（AI）只找线索，**不作为法条依据**
2. 五态判定：一致 / 部分一致 / 错误 / 遗漏 / 存疑
3. `verified` 只能由你打
4. 每条结论必须能追溯到原文条款号
