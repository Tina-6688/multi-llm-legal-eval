## 一、材料投放原则：最小可用 + 排除干扰

每个盲评工作区按「最小可用」原则投放材料——**只给完成当前任务所必需的文档，并主动排除可能引入噪声的干扰项**。

| 投放                     | 不投放            | 理由                |
| ---------------------- | -------------- | ----------------- |
| 本法评分标准                 | 非当前窗口评审所需的任何材料 | 防跨法/外部噪声干扰        |
| 本法拆解指令                 | 历史目录的遗留文件      | 防污染               |
| **本法官方原文（用于核对条款号与引文）** | 联网检索           | **防凭记忆编造；统一引文基准** |
| 匿名样本                   | 匿名映射表          | 防身份泄露             |
| —                      | 运行日志、分析说明、评分历史 | 防锚定               |

### 设计动因

模型在材料不足时倾向于"自己想办法"：

1. 凭记忆补写法条 → **编造**
2. 自行联网检索 → **引入不可核来源、与给定版本冲突**
3. 要求扩大查看权限 → **越界**

**提供官方原文是堵住第 1、2 种；指令中明令禁止是堵住第 3 种。**

### 「自行检索」的两种含义（易混，不可互换）

| 说法 | 指什么 | 性质 |
| --- | --- | --- |
| **样本生成阶段的自行检索** | 不给原文，由模型自行检索法条后作答 | **合法输入模式**（B 模式） |
| **裁判阶段的自行检索** | 裁判越界联网，引入未投放来源 | **违规行为** |

两者不是同一件事：前者是被评测的**输入条件**，后者会**污染评测**。本协议中凡出现"禁止检索"，一律指后者。

## 二、隔离的两层设计

本评测的隔离不是"在指令里写一句不许偷看"，而是两层独立控制，任何一层单独失效都不会导致身份泄露。

| 层           | 类型   | 实现方式                  | 挡住什么                   |
| ----------- | ---- | --------------------- | ---------------------- |
| **第一层（主）**  | 技术控制 | 每个窗口的工作区独立，只能访问被投放的材料 | 越权读取文件；即使想读也没有路径       |
| **第二层（强化）** | 程序控制 | 指令中列明「绝对不能看的材料」清单     | 模型在材料不足时申请扩权、自行检索、试探边界 |

### 为什么需要第二层

技术隔离解决的是"读不到"，解决不了"想要"。

实际观察到模型在材料不足时会主动声明材料不完整、建议自行检索、或按记忆补写条款。这三种行为都会污染盲评，因此第一层之外必须在指令层明确禁止，并配合人工抽查（检查输出中是否出现未投放材料的内容）。

## 三、标准执行顺序

三个阶段**严格串行**，前一阶段的输出是后一阶段的唯一输入：

```text
① 盲评 ──→ ② 汇总 ──→ ③ 配对分析
```

| 阶段       | 指令                | 能看什么                    | 绝对不能看              |
| -------- | ----------------- | ----------------------- | ------------------ |
| **① 盲评** | `01_盲评评审官指令.md`   | 本法评分标准、拆解指令、匿名样本、本法官方原文 | 匿名映射表、旧目录遗留文件、运行日志 |
| **② 汇总** | `02_汇总窗口指令.md`    | 三份分法盲评结果与明细 CSV         | 原始样本（不重打分）、模型身份    |
| **③ 配对** | `03_同模型配对分析指令.md` | 汇总表 + 匿名映射表             | 原始模型输出             |

**关键约束：分数锁定前，映射表不进入任何盲评工作区；只有在 ① 全部完成后，③ 才允许启用身份映射。**

### 分步投放

同一工作区内也分层投放：

- `覆盖审计参考/`（条款索引）**第一遍不看**，第二遍覆盖审计才打开；
- 分法结果参考材料**在汇总前不投放**，写汇总分析时才提供。

理由：先独立评分，再看参考，避免参考材料反向影响第一遍判断。

## 四、中断与恢复

### 发生了什么

7 个盲评窗口中，**3 个因物理原因（电脑锁屏 / 休眠导致连接中断与进程停止）中途停止**，未产出评分结果，损耗约 **5000 万 Token**。

### 怎么处理

**不在原窗口硬续，而是重建干净目录、重开窗口。**

![工作区列表：两组工作区显示名相同、上级目录不同](figures/workspace_isolation.png)

上图是评测期间的工作区列表（部分保留）。注意两组工作区的**显示名相同、上级目录不同**：

| 区域  | 会话名                                                   | 上级目录          | 说明                    |
| --- | ----------------------------------------------------- | ------------- | --------------------- |
| ②   | `独立盲评评分流程`<br>`法律样本盲评评分规范`<br>`匿名样本六维盲评评分`            | 新建的 `三法盲评_重启` | **重建后**的三个盲评工作区       |
| ①   | `任务中断_独立盲评评分标准`<br>`任务中断_法条拆解盲评评分`<br>`任务中断_法律样本盲评评分` | 原始的 `三法盲评`    | **中断的**三个盲评窗口，现场保留未删除 |

两组在界面上都显示为「网安法 / 个保法 / 数安法」，**只看名字分不出来**——只有上级目录不同。这正是重建时不覆盖旧目录、而是另建一个的原因：**旧现场完整保留，可用于事后归因。**

重建的根本原因不是"中断"本身，而是**原目录已被过程产物污染**：

- 目录里堆积了大量临时脚本、中间输出、调试文件（约 170 个文件）；
- 这些过程产物**没有任何结果文档输出**，却构成噪声源；
- 裁判窗口一旦看到这些杂项，容易被暗示或分心。

因此重建后的目录**只保留**：评分标准 + 拆解指令 + 官方原文 + 匿名样本（+ 第二遍才打开的条款索引）。

### checkpoint 的实际形态

需要说明的事实：**checkpoint 不是写在指令里的条款，而是执行纪律。**

指令要求「每次只评一份样本」并输出明细 CSV，等价效果是**边评边落盘**——单份评分不会因后续中断而丢失。这一做法后来被写入复盘 SOP，没有作为硬性条款嵌进指令文本。
